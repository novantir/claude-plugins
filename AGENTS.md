# AGENTS.md — claude-plugins

The `novantir/claude-plugins` marketplace: Novantir's Claude Code plugins and skills (`secret-input-card`, `novo-projeto`, `staging-vostro`, `full-stop-send`, `revisao-pr`, `ronda`).

This is the repository's only instructions file. It applies together with Rafael's global rules (`~/.claude/CLAUDE.md`); where they differ, this one prevails.

## 1. What it is

- **Takes care of:** the skills and plugins Rafael installs in Claude Code with `/plugin install <plugin> --marketplace novantir/claude-plugins`. A plugin is a folder in `plugins/<plugin>/` with `.claude-plugin/plugin.json`, `README.md`, `LICENSE` and, depending on the case, `skills/<skill>/SKILL.md`, `hooks/` and `tests/`. The [`marketplace.json`](.claude-plugin/marketplace.json) lists what is published.
- **Plugins today:** `secret-input-card` (a key without going through the chat; hooks in TSX, with tests and a privacy policy), `novo-projeto` (a project is born in the right category, with the template's `AGENTS.md` in `skills/novo-projeto/templates/`), `staging-vostro` (the `publicar-no-lab` skill, which follows the `servidor-vostro` manual), `full-stop-send` (issue → merge-ready PR, with a stop or a merge as the repo allows, and the issue's closing with a case study), `revisao-pr` (PR review with verified findings), `ronda` (periodic maintenance in five modes: health, security, dependencies, docs and code).
- **Neighbors in `oficina/`:** `claude-config` (global rules), `cockpit` (monitor), `flux-capacitor` (app factory), `servidor-vostro` (lab). Do not duplicate what already lives in one of them; point to it. The knowledge that applies to a whole category of project lives in the `novo-projeto` templates, not in the projects.

## 2. Stack

Markdown and JSON for skills and manifests. `secret-input-card` has hooks in TypeScript/TSX (`hooks/register.tsx`) and `.test.tsx` tests; the types in `.claude-plugin/types/` are generated by Claude Code when it loads the plugin and stay out of git. No external dependency beyond `claude` itself.

## 3. How to run and validate

For each plugin touched, in this order:

```bash
claude plugin validate plugins/<plugin>
claude plugin test plugins/<plugin>
```

To test a skill for real, install the plugin from the local folder in a session and use the skill in a rehearsal repository; `/plugin install` through the marketplace only sees what has already been sent to GitHub.

## 4. Conventions

- **Language:** the global rule applies ("Language" in `~/.claude/CLAUDE.md`). The marketplace is public, so the root README, the `plugin.json` files, `marketplace.json` and the plugins' READMEs are in English. `SKILL.md` files and the templates of files the AI reads (such as the `AGENTS-*.md` templates of `novo-projeto`) are in English too; the trigger phrases in each skill's `description` and the templates of text that reaches Rafael stay in Portuguese. `secret-input-card`, which serves anyone, is entirely in English.
- Commits so far in English, in the format `<plugin>: description` (see `git log`), and `type: description` for what is not about a single plugin. Switching commits to Portuguese: to be decided.
- When a plugin changes, bump the `version` in its `plugin.json` (`secret-input-card` is already at 0.1.9 because of that), and its description in `marketplace.json` stays the same as the manifest's.
- Identifiers in English. Small commits.
- Runs the same on both machines with Claude (MacBook Pro and Alienware).
- Every rule change in a `novo-projeto` template has a date and a reason in the commit message.

## 5. Critical rules

- Secrets never in this repository, in a test, fixture or log; `.env*` and `*.key` are in `.gitignore`. `secret-input-card` exists so the key's value never shows up: any change to it preserves that (value only in the plugin's memory while the card is open, error messages without the value).
- Read-only inside the projects where the skills run, except what the skill exists to create (`novo-projeto` creates the new folder; `full-stop-send` creates the branch, commits and PR of the repo it runs in, and at closing writes in the issue, creates the leftover issues and edits `docs/troubleshooting/` and the canonical docs in `docs/`; `ronda` writes the snapshot in `.claude/ronda/`, edits `README.md`, `AGENTS.md` and the indexes in `docs` mode and touches manifests in `deps` mode, both only with Rafael in the session, and does one small cleanup per area in `codigo` mode, always in the working tree and without git; in a routine, it writes nothing beyond the snapshot and posts the report in a single comment on the routine issue named by the repository's settings, and nothing else outside the repository).
- What reaches the other machines and whoever installs the marketplace goes out through the push: **push only with Rafael's OK.** MIT license on everything; `secret-input-card`'s `PRIVACY.md` goes with the public listing.

## 6. Workflow

- A PR and a stop before the merge (**Full Stop**, `full-stop-send` plugin).

## 7. Reminders

- `staging-vostro` only works on a machine that has the `servidor-vostro` repository and SSH access to the lab: the skill keeps the flow, the manual keeps the details.
- A new skill only when none of the existing ones can take the case as a step or a mode: `fechar-task` became section 7 of `full-stop-send` and the five Ansora routines became the modes of `ronda` (2026-11-13). What belongs to a single repository goes into its settings in `docs/processo/`, not into a skill in the repository.
- When filling in an `AGENTS.md` and noticing a rule that was missing from the category template, the change is a PR here, in `plugins/novo-projeto/skills/novo-projeto/templates/`.
